## 4. قيود بيئية يجب معرفتها قبل أي عمل

1. **السيرفر المثبَّت لا يحمل تعديلات المصدر.** كل تحقق يجري بتشغيل `server.js` من المصدر عبر اختبارات `e2e-*` (Electron + `ELECTRON_RUN_AS_NODE=1`).
2. **`pnpm install` العادي يفشل** عند `packages/server-desktop postinstall` (‏`electron-builder` يطلب `prebuild-install` لإعادة بناء `better-sqlite3`). العمل المتبع: `pnpm install --ignore-scripts` — وثنائي `better-sqlite3` المبني لـElectron يبقى سليماً.
3. **قفل واجهة VMware:** تشغيل الـVM بـ`gui` قد يفشل بـ`Unknown error` إذا كانت الواجهة مفتوحة. المتبع: إغلاق الواجهة، حذف `*.vmx.lck` المعلّق، ثم `vmrun start` (يعمل `nogui`).
4. **الوكيل يعمل `asInvoker`** — التشغيل بصلاحيات إدارية يأتي من طريقة التشغيل لا من التطبيق.
5. **`ws-ticket` أحادي الاستخدام** بصلاحية 30 ثانية — أي مسبار يفتح مشاهدين يحتاج تذكرة لكل واحد.
6. **بيانات المختبر** في `%APPDATA%\AiRemote\lab-credentials.txt` و`lab-probe.json` — لا تُطبع ولا تُرفع.

## 6. نقطة الاستئناف الدقيقة

**المهمة التالية بالضبط:** إغلاق **بقايا R4** ثم **R5**، بهذا الترتيب:

1. **قياس 20 جلسة متزامنة** على الاستضافة الحالية (بوابة الخطة: لا تدهور يتجاوز 15%). الأداة: مسبار يفتح مقابس وكلاء متعددة ويمرّر بايتات عبر `relay:data` ويسجّل p50/p95 للزمن والبايتات المُسقَطة. القياس وحده يُثبت أو ينفي السقف.
2. **حالة `suspended` (إعادة ربط خلال 15 ثانية):** اليوم أي انقطاع يُغلق الجلسة بسبب `network`. المطلوب: مهلة سماح واحدة، ثم إغلاق نظيف مع سبب — مع اختبار يقطع المقبس ويعيده داخل المهلة.
3. **واجهة «اتصال بجهاز»** وشاشة الموافقة على الطرف الهدف — **مؤجّلة إلى R6 بقرار مكتوب** (البروتوكول والمسارات جاهزة).
4. ثم **R5 — نقل ملفات:** تجزئة 1MB، استكمال بنقطة محفوظة (`file_transfers`)، SHA-256 بعد الاكتمال، رفض `..`/symlinks، وسياسة تعارض مكتوبة.

**تمهيد R4 أُنجز:** `docs/PROTOCOL-RELAY-AR.md` يوصّف §4.4 كما نُفِّذ (بما يخالف النص الأصلي: ضمّ `accepted` داخل مسار القبول، واستهلاك الرمز مرة لكل طرف بدل مرة مطلقة).

**قيود يجب احترامها:** لا حذف بلا موافقة، لا `push`، لا تغيير شهادة/ترخيص، وكل خطوة تُختبر وتُوثَّق في `outputs/verify-YYYY-MM-DD/` قبل الالتزام.
