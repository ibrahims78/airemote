# إصدار 3.16.6 — إشعار نتيجة المهمة المجدولة + التحقق من شعار الترحيل

## 1) نتيجة المهمة المجدولة تصل إلى Telegram
كانت المهمة تُحفظ نتيجتها في قاعدة البيانات وتُنشئ إشعارًا داخل التطبيق فقط؛ من يشغّل مهمة ليلية
لا يعلم بنتيجتها إلا إذا فتح اللوحة. الآن `runTask` يُطلق حدثًا مستقلًا `task`.

| القياس | النتيجة |
|---|---|
| `POST /api/settings/telegram/notify` بمفتاح `kind=task` | `200 {"ok":true,"kind":"task"}` |
| مهمة `exec` حقيقية على المحاكي | `exit=0` + `TASK-TELEGRAM` في `last_result` |
| تعطيل مفتاح «نتائج المهام» ثم الإرسال | `400 not sent` (منع فعلي) |
| إعادة التفعيل | `200` |
| المفتاح في الواجهة | أربعة مفاتيح: اتصال · انقطاع · دردشة · **نتائج المهام** |

صيغة الرسالة: `✅ مهمة نُفِّذت: <الاسم>` أو `⚠️ مهمة فشلت: <الاسم>` ثم أول 400 محرف من النتيجة.

## 2) شعار الترحيل (relay) على بطاقة الجهاز — اختُبر فعليًا
كان الحقل `relay` يساوي `null` على كل الأجهزة، فلم يكن الشعار قد ظهر قط. أنشأنا جلسة ترحيل حقيقية:

1. `POST /api/relay/request` إلى **WIN10-VM** بصلاحية `view` → `201` · الحالة `requested`
2. `POST /api/relay/<id>/decision {accept:true}` → `200` · الحالة **`active`**
3. قراءة `/api/devices`: `relay = {state:"active", access:"view", peerName:"admin@airemote.local"}`
4. صفحة الأجهزة أظهرت على صف WIN10-VM: **«قطع · عرض · LIVE · admin@airemote.local»** مع نقطة حمراء
5. إغلاق الجلسة `POST /api/relay/<id>/close` → `200`، وعاد الحقل إلى `null`
