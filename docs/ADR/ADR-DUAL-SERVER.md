# ADR — السيرفران: الحياة هي server-desktop (W1-3)

| | |
|---|---|

## السياق

المشروع يحمل سيرفرين منفصلين — حاجز معماري من فحص 68.5/C:

1. **`packages/server`** — TypeScript نظيف، إصدار **3.14.0**، fastify **4.x**. ورد في README القديم وكأنه السيرفر.
2. **`packages/server-desktop/server.js`** — **7,182 سطراً** JavaScript، إصدار **3.16.19**، وهو ما يُشحن فعلاً: `scripts/bundle.js` (esbuild) → `server.bundle` → `main.js` → **`app.asar`**.

`PROJECT_STATE.md` §0.0 (2026-11-08) يقرّ حرفياً بأن `packages/server` (TS) **«غير مشحون في أي حزمة»**. فخّ 88: أي إصلاح في TS وحده لا يصل الحزمة المشحونة.

## الخيارات

| # | الخيار | التقييم |
|---|---|---|
| أ | **الحياة هي `server-desktop`** — إعلان `packages/server` مرجعاً تعليمياً مجمداً | **المختار** — صادق مع الواقع المقيس، صفر مخاطرة تشغيل، يغلق الحاجز بقرار مكتوب لا بحذف كود |
| ب | توحيد تدريجي: نقل مسارات الحياة من `server.js` إلى TS على موجات لاحقة | صحيح هندسياً لكنه مشروع كبير؛ خارج نطاق W1 — يُدرَس في W3 (بند 8) بلا تنفيذ بلا قرار جديد |
| ج | دمج فوري | مرفوض في W1 — خطر بلا اختبار كافٍ |

## القرار

**الخيار (أ).**

1. `packages/server-desktop/server.js` هو **مصدر الحقيقة المشحون**.
2. `packages/server` = **مرجع تعليمي/مجمد** — أُعلن ذلك في `packages/server/README.md` (ويُكتب في README الجذر ضمن W2-1).
3. ثغرات fastify 4.x العالية في هذه الحزمة مقبولة موثّقة بـ`docs/ADR/FASTIFY-SECURITY.md` لأنها غير مشحونة.
4. أي عمل مستقبلي على السيرفر يستهدف `server.js` الحيّ إلا بقرار صريح من المالك.

## النتائج

- حاجز «ازدواجية مصدر الحقيقة في السيرفر» يُغلق بقرار مكتوب.
- بوابة `check-version-consistency.cjs` تُشغَّل بـ`--allow-missing-server` لأن حزمة TS (3.14.0) ليست جزءاً من توحيد الإصدار المشحون — يبقى الوضع حتى قرار توحيد جديد.
- W3-8 يحدّث هذا الـADR فقط إن قُرر التوحيد (لا تنفيذ بلا طلب).
