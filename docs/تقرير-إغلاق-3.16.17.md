# تقرير إغلاق 3.16.17 — تنفيذ P1–P4 و S1–S3 كاملة

> التاريخ: 2026-11-12 · الفرع: `feat/screen-unify-3.13.0` · أمر المالك: «نفّذ ما يستحق العمل فعلًا كاملًا واحترافيًا».
> **النتيجة:** وكيل أندرويد صار يطابق وكيل ويندوز في عقد المساعد الذكي (بث + محادثات + تنفيذ كتل)، مع فقاعات دردشة، بطاقة جهاز كاملة، أدوات سجل، شارات بث، ولمسات تصميم — مضغوطة في **3.16.17 (versionCode 107)** مثبَّتة على السيرفر + وكيل ويندوز + المحاكي + TECNO.

---

## 1) ما نُفِّذ — بندًا بندًا

### P4 — عقد المساعد الذكي في أندرويد (جديد كليًا: `AiClient.java`)
| المكوّن | التنفيذ |
|---|---|
| البث | `POST /api/ai/chat/stream` بقراءة SSE (أسطر `data:`، تجاهل `[DONE]`، تبنّي `conversationId` من أول حدث) — نفس قواعد `main.js` في ويندوز حرفيًا |
| السياق | إرسال `deviceId` + `conversationId` (كانا مفقودين) + حقل `context` يوجّه النموذج لاستخدام `shell/bash/screenshot/control` على أندرويد بدل PowerShell |
| الإيقاف | محلي عبر `disconnect()` — لا طلب للسيرفر (مطابق `AbortController`) |
| المحادثات | `GET /api/ai/conversations?deviceId=` · `GET /api/ai/history` · `DELETE /api/ai/conversations/:id` · تخزين `aiConvId` في SharedPreferences (مقابل ملف JSON في ويندوز) |
| تنفيذ الكتل | `shell/bash/cmd/sh` عبر `sh -c` (مهلة 120ث، حدود 20k/4k) · `screenshot` عبر `MediaProjection` (مسار `captureToFile` القائم) بصورة JPEG داخل `data:image/jpeg;base64` · `control` عبر `AiRemoteA11y` بجميع التعليمات الاثنتا عشرة · `powershell`/`record` رفض واضح كما في ويندوز |
| الأمان | نفس حارس الأوامر الخطرة + تأكيد صريح + **لا تنفيذ تلقائي إطلاقًا** (قرار 3.16.16) |

### P1 — فقاعات الدردشة + سجل المحادثات
- فقاعات رسائل للمساعد والدردشة: رسائل المستخدم بلون التمييز جهة النهاية، ردود المساعد/المشاهدين بسطح مغاير جهة البداية (سلوك RTL سليم).
- كتل الكود داخل الرد: تسمية اللغة + زر نسخ + زر تنفيذ + نتيجة ملوّنة + صورة اللقطة داخل الفقاعة.
- **زر «السجل»** يفتح قائمة المحادثات (عنوان + تاريخ + حذف)، والنقر يحمّلها؛ واسترجاع آخر محادثة تلقائيًا عند الاتصال (مقابل `ai-ready` في ويندوز).
- الاسترجاع بعد `recreate()` (تبديل الثيم/اللغة) صار عبر قوائم منظمة بدل النصوص.
- تم التحقق حيًّا على المحاكي: إرسال «hello» → فقاعة مستخدم زرقاء → رد عربي متدفق بالفقاعة → زر الإيقاف ظهر أثناء البث واختفى بعده.

### P2 — بطاقة معلومات جهاز كاملة
- صفان جديدان في بطاقة الاتصال: **IP المحلي** و**IP العام**، كلٌّ منهما بزر نسخ، ومعرّف الجهاز يُنسخ بضغطة طويلة.
- IP العام يُجلب مرة واحدة من `api.ipify.org` (نفس مصدر وكيل ويندوز) ويُرسل في حزمة التسجيل `info.ipPublic` (كان `""` دائمًا).
- تحقق حي: المحاكي `192.168.1.12 / 155.37.96.5` وTECNO `192.168.1.101 / 155.37.96.5` — مع أزرار نسخ.

### P3 — أدوات السجل + قوة كلمة السر
- سطور السجل أصبحت موسومة بالمستوى (`I`/`W`/`E`) مع ترقية 9 مواضع خطأ/تحذير في الخدمة.
- **فلترة بالمستوى**: الكل / معلومات / تحذيرات / أخطاء (أزرار انتقائية ملوّنة).
- **تصدير**: إلى «التنزيلات» عبر `MediaStore` (أندرويد 10+) وإلى مجلد التطبيق في الأقدم، مع إشعار المسار.
- **شريط قوة كلمة السر** تحت حقل كلمة مرور التحكم: تقييم (طول + تنوع محارف) بأربعة مستويات ملوّنة (ضعيفة/متوسطة/جيدة/قوية) — تحقق حي: `Test1234` → «جيدة».

### S1 — شارات البث/الخصوصية
- شارتان في بطاقة الحالة: **«التقاط جاهز / الالتقاط غير ممنوح»** (أخضر/تحذيري) و**«بث مباشر»** (يظهر فقط أثناء البث)، تتحدثان من نبض القلب كل 5 ثوانٍ.
- تحقق حي: على TECNO ظهرت «التقاط جاهز» بالأخضر بعد المنح، وعلى المحاكي «الالتقاط غير ممنوح» قبله.

### S2 — توحيد ارتفاع الأزرار 44dp
- XML: `log_search` و`btn_copy_log` 42→44، و`btn_auth_consent/btn_auth_password/btn_save/btn_del_pw/btn_clear_log` 40→44.
- Java: أزرار «تحديث/طلب الاتصال/تحديث الجلسات/قطع» المبنية برمجيًا حصلت على 44dp صريحة (كانت بلا ارتفاع محدد).
- أزرار نسخ الـIP تُركت 32dp عمدًا (رقاقات مصغّرة كشرائح الرأس).

### S3 — خط العناوين العربية
- `sans-serif-medium` على عنوان التطبيق وعنوان الحالة وعنواني الأقسام وعناوين البطاقات المبنية في Java (بدل bold الزائف).

## 4) حالات لم تُغلق (بقرار/قيد)

1. **التقاط الشاشة على المحاكي:** بعد أي إعادة تثبيت يسقط المنح، وطلب الإذن التلقائي مقيّد بـ«مرة كل 6 ساعات»، فلم يظهر الحوار عند `requestCapture` عبر `onNewIntent`. **المنح يدوي من معالج التهيئة → التقاط الشاشة** (نقرة واحدة). على TECNO مُنح ويعمل. هذا سلوك قديم وليس رجوعًا في هذه الجولة.
2. **تنفيذ كتل `control` على المحاكي/TECNO** لم يُختبر حيًّا داخل هذه الجولة (يتطلب جلسة عارض نشطة) — الكود ملتزم والمنفّذ يعتمد على `AiRemoteA11y` المختبرة سابقًا عبر أوامر الخادم.
3. وكيل ويندوز على هذا الـPC: مثبَّت 3.16.17 ويعمل، ولا يزال بلا `serverUrl/token` (كما كان قبل الجولة — لم يكن مسجلًا على السيرفر أصلًا).

## 5) مخاطر وملاحظات

1. **بث SSE في الخلفية:** الطلب يستمر لو غادر المستخدم التبويب (مثل ويندوز)؛ الإيقاف من زر «إيقاف» فقط.
2. **حد المزود المجاني** (~رد/30ث) يديره السيرفر — أندرويد يتلقى الرسالة جاهزة، ولا حاجة لمعالجة خاصة.
3. `MAX_MSGS = 200` لكل محادثة في الذاكرة — منع تضخم الواجهة؛ التاريخ الكامل من السيرفر.
4. الطرفية/الإيقاظ (WOL) تبقى ويندوز فقط — معلنة في بطاقة «أندرويد» القائمة.
