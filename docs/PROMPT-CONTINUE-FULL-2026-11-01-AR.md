## 4) المراحل — نفّذها بالترتيب، ولكل مرحلة معيار قبول مُقاس

### P0 — خط الأساس (بلا تغيير كود)
- `verify.js` 40/40 · `scan-ui-colors` 0 · `check-contrast` 22/22 · `tsc` 0 · `release-manifest --verify` سليم.
- سجّل الأرقام في `outputs/verify-<date>/p0-baseline/REPORT-AR.md`.

### P1 — إصلاح العيوب المعروفة (أعلى أولوية بعد P0)
1. **حد كلمة المرور:** الواجهة تقبل 8 والسيرفر يرفض < 12 (`SetupPage.tsx` ↔ `server.js`) — وحّد الحد ورسالة الخطأ.
2. **تدقيق تغيير الدور:** لا حدث تدقيق مخصّص؛ أضفه وأثبته.
3. **الاحتفاظ:** حذف صفوف التدقيق لا يُسجَّل في التدقيق نفسه — أصلحه.
4. أي عيب يظهر في P0 أو من المساعدين 1–3 (بعد إثباته).
**القبول:** اختبار جديد لكل عيب يفشل قبله وينجح بعده (أضفه إلى `verify.js` إن أمكن دون كسر العدّ الموثّق، أو كسكربت مستقل + دليل).

### P2 — تطوير البث ليكون احترافياً
- **إطارات:** سياسة keyframe واضحة (عند الانضمام المتأخر، تغيير الدقة/الشاشة، تدوير، تغيير الجودة) · لا إعادة تشغيل التقاط عند تغيير الجودة (3.9.9) · صحّة delta عند تغيّر الأبعاد.
- **شبكة:** إعادة اتصال بمفتاح `rk` بلا فقد إطارات · مؤشرات (fps/latency/bitrate) دقيقة · سلوك عند انقطاع الوكيل.
- **حالات:** شاشة مقفلة/بث محمي/إذن مفقود — رسالة واحدة موحّدة تختفي تلقائياً (لا تُغطي الصورة).
- **أداء:** هدف p50 نقر ≤ 80ms وأول إطار ≤ 1.2s (LAN) — قِسه مقابل `docs/perf-baseline.json`.
- **تسجيل:** T15 داخل الجلسة (h264+aac · مدة ±1s · `ffprobe`).
**القبول:** أدلة في `outputs/verify-<date>/stream/` + T15 + T18 (انحدار ≤10%).

### P3 — توحيد «طلب الاتصال» بين ويندوز وأندرويد
- مسار واحد: قائمة أجهزة → اختيار مستوى الوصول (عرض/تحكم) → كلمة مرور إن لُزمت → إرسال → حالات (معلّق/مقبول/مرفوض/منتهٍ/تعارض) بنفس النصوص والترتيب.
- نفس المصطلحات في المنصّتين (`طلب تحكم` · `بانتظار الموافقة` · `رفض` · `إلغاء`).
- **القبول:** جدول توافق (نص/حالة/زر) + لقطتان من كل منصّة لنفس السيناريو.

### P4 — توحيد واجهة الوكيل (ويندوز + أندرويد)
- نفس هيكل الأقسام: الحالة · الأجهزة · الجلسات · السجل · الإعدادات.
- نفس مفردات الحالة (متصل/جارٍ الاتصال/غير متصل) ونفس موضع رقم الإصدار.
- **القبول:** لقطات مقابلة + جدول تطابق + لا نص مقطوع عند 360px و1920px (T16).

### P5 — اختبار شامل
- **بوابات:** البطارية 40/40 · ألوان 0 · تباين 22/22 · tsc 0.
- **أجهزة:** WIN10 وWIN11 (هدفاً وطالباً) · TECNO وEmulator (هدفاً وطالباً) · كل اتجاه تحكم (ويندوز→ويندوز · أندرويد→ويندوز · ويندوز→أندرويد · أندرويد→أندرويد).
- **T8** 20 جلسة متزامنة · **T13** نقل 1GB داخل جلسة · **T12** الحافظة · **T14** الدردشة · **T10/T11** التدوير والقيد · **T9** الخلفية.
- **الأخطاء المكتشفة:** أصلحها، وأضف دليلاً لكل إصلاح.
- **القبول:** ملف واحد `outputs/verify-<date>/full-matrix/REPORT-AR.md` بجدول (بند · متوقع · فعلي · دليل · PASS/FAIL/BLOCKED).

> **عقبة معروفة:** تحكم ويندوز→أندرويد يحتاج **إذن التقاط الشاشة** على الهاتف (مربع حوار نظام). اطلبه من صاحب الجهاز، ولا تعتبره عيب كود.

### P6 — توحيد الإصدار (إلزامي في النهاية)
1. **مصدر واحد للحقيقة:** ملف `VERSION` في جذر المستودع (مثلاً `4.0.0`) تقرأه كل الحزم (`server-desktop` · `agent-desktop` · `android-agent` · `dashboard`) وتُبنى منه.
2. **العرض في كل مكان بنفس القيمة:**
   - السيرفر: `/health` + `/ready` + ترويسة اللوحة + صفحة الدخول + تذييل اللوحة.
   - وكيل ويندوز: عنوان النافذة + شاشة «حول» + سجل الاتصال.
   - وكيل أندرويد: ترويسة التطبيق + «حول» + `versionName` و`versionCode` في APK.
   - أسماء الحزم: `AiRemote-Server-…-v4.0.0` · `AiRemote-Agent-…-v4.0.0` · APK.
3. **تحقّق آلي:** سكربت `scripts/check-version-consistency.cjs` يقارن (VERSION · package.json ×4 · build.gradle · /health · manifest.json) ويفشل عند أي اختلاف — أضفه خطوة في البطارية.
4. **القبول:** تشغيل السكربت = PASS + لقطات من المواضع الأربعة تُظهر نفس الرقم + بيان الإصدار موقّع ومطابق.
