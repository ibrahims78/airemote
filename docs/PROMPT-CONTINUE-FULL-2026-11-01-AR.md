## 3) المساعدون — القدرات، والحل المعتمد للعمل من أي حساب

### 3.1 افحص القدرات أولاً (خطوة إلزامية قبل أي تفويض)
أطلق **مساعداً مؤقتاً واحداً** بهذه المهمة الحرفية:

> «اذكر أسماء أدواتك. إن كانت لديك أداة تنفيذ أوامر فشغّل `node -e "console.log('EXEC_OK')"` وأعد المخرجات،
> وحاول قراءة أول سطر من `D:\autoclaw projects-new\AiRemote\package.json`. إن لم تملك ذلك اكتب `NO_EXEC` فقط،
> واذكر ما تملكه من أدوات.»

**نتيجة هذا المضيف (مقيسة):** المساعدون **لا يملكون تنفيذ أوامر** (14 أداة: `ls · read · find · grep · write ·
edit · apply_patch · deliver_file · fetch_content · web_search · tool_search · …`)، وأدوات ملفاتهم **محصورة
في `<مجلد المشروع>`** ولا تصل إلى `D:\`. ووصف القدرة (`rw,exec`) في بطاقة الوكيل **ليس صلاحية فعلية**.

### 3.2 الفرع أ — إن كانت أداة التنفيذ متاحة (تحقّق فعلياً بـEXEC_OK)
فوّض مباشرة: كل مساعد ينفّذ ويقرأ من `D:\`، وأنت تتحقق من نتائجه بتشغيل الأوامر بنفسك.

### 3.3 الفرع ب — الافتراضي (لا تنفيذ): **مرآة المصدر + رقع موحّدة**

**أ) ابنِ المرآة** (مستقلة عن الحساب: تكتب في `<مجلد المشروع>\mirror`):
```powershell
cd '<مجلد المشروع>'
node 'D:\autoclaw projects-new\AiRemote\tools\lab\a2a\mirror-sync.cjs'
#   → <مجلد المشروع>\mirror\src  (≈396 ملفاً · 9.8 MB)
#   → INDEX.txt · META.json
node 'D:\autoclaw projects-new\AiRemote\tools\lab\a2a\mirror-sync.cjs' --check   # تحقّق من الملفات الحرجة
```
- السكربت يرفض الكتابة داخل المستودع، ويستبعد `node_modules · dist · releases · outputs · build · .gradle · .git`.
- خيارات: `--repo <path>` · `--out <dir>` · `--check`. المتغيّرات: `AIREMOTE_REPO` · `AIREMOTE_MIRROR`.

**ب) أعطِ كل مساعد مهمة على المرآة** — مثال:
> «اقرأ `mirror/src/packages/agent-desktop/main.js`. أعد: رقم سطر `injectMouse`، والسطرين الذين يحسبان
> `xi/yi`، وهل يُضاف `capOriginX/Y`، ورقم `case 'server:screen_mouse'`. انقل الأسطر حرفياً. لا تخمّن.»

**ج) مخرجات المساعد المقبولة هي واحدة من اثنتين:**
1. **تحليل بدليل** `file:line` + النص الحرفي.
2. **رقعة موحّدة** تُكتب في `<مجلد المشروع>\patches\<شريحة>.patch` بهذا الشكل:
```
--- a/<مسار داخل المستودع>
+++ b/<مسار داخل المستودع>
@@ ...
-السطر القديم
+السطر الجديد
```
مع: سبب التغيير · الأثر المتوقع · اختبار يقترحه · ما يجب أن يظل كما هو.

**د) أنت (المنفّذ الوحيد) تطبّق وتتحقق:**
```powershell
cd 'D:\autoclaw projects-new\AiRemote'
git apply --check '<مجلد المشروع>\patches\<شريحة>.patch'      # فحص أولاً
git apply '<مجلد المشروع>\patches\<شريحة>.patch'
node --check <الملف المعدّل>
node scripts\verify.js                                         # 40/40
```
أو استخدم `tools\lab\a2a\patch.cjs` (يرفض التكرار أو انكماش الملف) بملف مواصفات JSON.

**هـ) أعد مزامنة المرآة بعد كل تغيير** حتى لا يعمل المساعدون على نسخة قديمة:
```powershell
node 'D:\autoclaw projects-new\AiRemote\tools\lab\a2a\mirror-sync.cjs'
```

**و) لا تكتب داخل `mirror\` أبداً** — هي لقطة قراءة فقط، وأي تعديل يجري في المستودع الحقيقي عبرك.

- مساعد أعاد `NO_EXEC` أو فشل → **أعد المحاولة مرة واحدة** بمهمة أضيق (ملف واحد / سؤال واحد).

## 4) المراحل — بالترتيب، ولا انتقال قبل معيار القبول

### P0 — خط الأساس + تجهيز العمل

### P1 — إصلاح العيوب المعروفة
1. **حد كلمة المرور:** الواجهة تقبل 8 والسيرفر يرفض < 12 (`SetupPage.tsx` ↔ `server.js`) — وحّد الحد والرسالة.

3. **الاحتفاظ:** حذف صفوف التدقيق لا يُسجَّل — أصلحه.
4. أي عيب يثبته المساعدون 1–3.
**القبول:** اختبار يفشل قبل الإصلاح وينجح بعده + دليل.

### P2 — تطوير البث ليكون احترافياً
- سياسة keyframe: انضمام متأخر · تغيير دقة/شاشة · تدوير · تغيير جودة (بلا إعادة تشغيل التقاط).
- صحّة delta عند تغيّر الأبعاد · إعادة اتصال بـ`rk` بلا فقد إطارات · مؤشرات fps/latency/bitrate دقيقة.
- حالات موحّدة (مقفل/بث محمي/إذن مفقود) برسالة واحدة تختفي تلقائياً ولا تحجب الصورة.
- **T15** تسجيل MP4 داخل الجلسة (h264+aac · مدة ±1s · `ffprobe`) · **T18** انحدار ≤10% مقابل `docs/perf-baseline.json`.
**القبول:** `outputs/verify-<date>/stream/` + T15 + T18.

### P3 — توحيد «طلب الاتصال» بين ويندوز وأندرويد
قائمة أجهزة → مستوى وصول → كلمة مرور إن لزمت → إرسال → حالات (معلّق/مقبول/مرفوض/منتهٍ/تعارض)
بنفس النصوص والترتيب في المنصّتين. **القبول:** جدول توافق + لقطتان لنفس السيناريو.

### P4 — توحيد واجهة الوكيل (ويندوز + أندرويد)
الأقسام: الحالة · الأجهزة · الجلسات · السجل · الإعدادات — بنفس المفردات وموضع رقم الإصدار.
**القبول:** لقطات مقابلة + لا نص مقطوع عند 360px و1920px (T16).

### P5 — اختبار شامل

**القبول:** `outputs/verify-<date>/full-matrix/REPORT-AR.md` (بند · متوقع · فعلي · دليل · PASS/FAIL/BLOCKED).

### P6 — توحيد الإصدار (إلزامي في النهاية)

**القبول:** السكربت PASS + لقطات من المواضع الأربعة + بيان إصدار موقّع.

## 5) قواعد ملزمة
- **شريحة واحدة = التزام واحد** (بناء + بوابات + دليل + CHANGELOG + PROJECT_STATE).
- لا تُطبع أسراراً؛ استخدم `tools\lab\a2a\vmguest.cjs` (يُنقّي) ولا تستدعِ `vmrun -gp` في مخرجات مرئية.

- **ممنوع الكتابة في `mirror\`** و**ممنوع تطبيق رقعة بلا `git apply --check` أولاً**.
