# خطة التطوير المقترحة — منصة AiRemote
> وثيقة مقترحات للاعتماد — أُعدّت بتاريخ 2026-10-16 — لا يتضمن هذا الملف أي تنفيذ، وهو للعرض والاختيار فقط.

## 1) الاقتراح الأقرب للتنفيذ: دردشة ذكاء مباشرة داخل نافذة الوكيل
**الفكرة:** إتاحة دردشة ذكاء اصطناعي كاملة داخل تطبيق الوكيل على الجهاز نفسه (وليس للمشاهدين)، بحيث يستطيع من يجلس على الجهاز التحدث مع المساعد الذكي وطلب تنفيذ المهام دون فتح لوحة التحكم.

**لماذا؟** ظهر لديك فعلياً التباس بين «دردشة المشاهدين» ودردشة الذكاء — هذه الميزة تنهيه تماماً وتجعل الوكيل بوابة كاملة.

**المتطلبات التقنية:** نقطة مصادقة محلية آمنة للوكيل + واجهة دردشة مطابقة للوحة (نفس القدرات: لقطة/فيديو/تحكم/ذاكرة) + حد استخدام منفصل.

**الأثر:** كبير على التجربة — العمل المتوقع: 2–3 أيام تطوير واختبار.

## 2) خارطة التحديث الشامل (المستوى العالمي)

### أ) السرعة والأداء
- تقسيم حزمة الواجهة (~1.2MB حالياً) إلى حزم لكل صفحة → تحميل أولي أسرع حتى 3 أضعاف.
- ضغط Brotli + ETag + تخزين مؤقت للأصول الثابتة.
- فك ترميز البث عبر WebCodecs في المتصفح + جودة تكيفية أذكى (CPU أقل ومعاينة أنعم).
- Runspace دائم في الوكيل بدل تشغيل PowerShell لكل أمر → تنفيذ أقل من 100ms بدل ~300–600ms.
- فهارس قاعدة بيانات + تنظيف دوري + ترقيم صفحات من الخادم + virtualization للقوائم الطويلة.

### ب) الأمان
- HTTPS/TLS كامل (شهادة تلقائية) + إجبار التشفير — الاتصال حالياً HTTP فقط.
- WSS وتشفير الحمولة بين السيرفر والوكيل بمفتاح خاص لكل جهاز.
- تفعيل التحقق بخطوتين (TOTP) — البنية جاهزة في قاعدة البيانات.
- إدارة جلسات (عرض الأجهزة المتصلة وإنهاء أي جلسة) + سياسات كلمات مرور أقوى.
- تحديد معدل موحّد لكل الـ API + سياسة CSP للواجهة + فحص ثغرات دوري (npm audit).
- تأكيد إلزامي للعمليات الخطرة قبل التنفيذ (حذف/إيقاف خدمات/أوامر غير عكوسة).
- تشفير النسخ الاحتياطية + سجل تدقيق غير قابل للتعديل (append-only).

### ج) الواجهة والتجربة
- نظام تصميم موحد (Tokens) + هياكل تحميل Skeletons + انتقالات ناعمة.
- منصة أوامر سريعة Ctrl+K للتنقل وتشغيل أي إجراء.
- PWA: تثبيت التطبيق على الجوال/سطح المكتب + إشعارات فورية Live.
- لوحة رئيسية قابلة للتخصيص + ثيم تلقائي حسب النظام.

### د) الميزات والموثوقية
- تعدد الأجهزة في محادثة واحدة (إدارة أسطول بالذكاء).
- قص تفاعلي للصور/الفيديو (تحديد منطقة بالسحب ثم حفظ/تسجيل).
- جدولة مهام داخلية: «كل يوم 9 صباحاً افحص القرص وأرسل ملخصاً».
- مراقبة استباقية بالذكاء + إصلاح ذاتي، وتحديث تلقائي للوكيل، ونسخ احتياطي/استعادة من الواجهة.
- **توسيع أدوات التحكم (جاهز جزء منه اليوم):** أوامر انتظار (wait)، النقر بالاسم (clickname)، إكمال المهام الطويلة خطوة بخطوة مع تحقق تلقائي.

## 3) تسلسل تنفيذ مقترح (4 أسابيع)
| الأسبوع | المحور |
|---|---|
| 1 | الأداء: تقسيم الحزم + ضغط + فهارس + Skeletons + أي مشاكل عاجلة |
| 2 | الأمان: TLS + WSS + TOTP + قيود المعدل + تأكيد العمليات الخطرة |
| 3 | التجربة: نظام التصميم + Ctrl+K + PWA + الجوال |
| 4 | الميزات: دردشة ذكاء في الوكيل + تعدد الأجهزة + الجدولة + المراقبة الاستباقية |

## 4) ملاحظات
- كل بند قابل للتفكيك والاعتماد منفرداً.
- الأولوية القصوى المقترحة: **دردشة الذكاء في الوكيل** (طلبك) ثم **الأداء** ثم **الأمان**.
- التنفيذ يبدأ فقط بعد اختيارك وموافقتك.
- توسعة الأندرويد (القسم 5) مسار مستقل يُعتمد منفصلاً عن خطة الأسابيع الأربعة.

## 5) إضافة بطلبك: وكيل أندرويد بنفس قدرات وكيل ويندوز

**الخلاصة:** نعم، ممكن — يمكن نقل معظم قدرات وكيل ويندوز إلى تطبيق أندرويد عبر واجهات النظام الرسمية، مع فروق إلزامية: كل قدرة حساسة تحتاج إذناً صريحاً من المستخدم (التقاط الشاشة يوافق عليه يدوياً، والتحكم يتطلب تفعيل خدمة إمكانية الوصول)، وبعض ميزات ويندوز العميقة (PowerShell الكامل، النفق الطرفي، تثبيت البرامج) لها مقابل محدود أو تتطلب صلاحيات إضافية متقدمة.

**جدول نقل الميزات:**
| وكيل ويندوز | المقابل في أندرويد | الجدوى |
|---|---|---|
| مشاهدة/بث الشاشة | MediaProjection (التقاط الشاشة الرسمي) + نفس بروتوكول البث | مباشر (بموافقة المستخدم) |
| التحكم بالفأرة/النقر | خدمة إمكانية الوصول: لمس/سحب/تمرير/رجوع/أزرار النظام | مباشر (تفعيل يدوي للخدمة) |
| النقر بالاسم (clickname) | شجرة عناصر الشاشة: البحث بالنص/الوصف والضغط المباشر | مباشر — وغالباً أدق من ويندوز |
| الكتابة النصية | ACTION_SET_TEXT على الحقل المركّز أو لصق | مباشر |
| لقطة شاشة | MediaProjection | مباشر |
| تسجيل فيديو | MediaProjection + MediaCodec | مباشر |
| فتح التطبيقات | Intent لإطلاق الحزم | مباشر |
| أوامر PowerShell | غير متاح — بديل محدود داخل بيئة التطبيق، أو Shizuku بصلاحيات ADB (متقدم اختياري) | محدود/اختياري |
| نفق طرفي/PTY | غير متاح بسهولة | يحتاج Shizuku/root |
| نقل الملفات | مجلد التطبيق + SAF للمجلدات المشتركة | مباشر |
| واجهة المشاهدين/الدردشة | نفسها — نفس بروتوكول السيرفر | مباشر |

**المراحل المقترحة للوكيل الأندرويد:**
- **A1 — نواة الاستخدام (أسبوعان تقريباً):** اتصال بالسيرفر + مشاهدة الشاشة + لقطة + تسجيل + تحكم أساسي (لمس/سحب/كتابة/أزرار النظام) + فتح تطبيقات + النقر بالاسم + دردشة المشاهدين.
- **A2 — الاكتمال (أسبوعان):** نقل ملفات ثنائي الاتجاه، إشعارات الجوال، تحسين البث والأداء، تحكم كامل من اللوحة.
- **A3 — اختياري متقدم:** تكامل Shizuku للأوامر المتقدمة، مزامنة الحافظة، أتمتة أوسع.

**اعتبارات إلزامية (فروق جوهرية عن ويندوز):**
- الأذونات: موافقة التقاط الشاشة لكل جلسة (وإلا خدمة أمامية دائمة حسب إصدار النظام)، وتفعيل خدمة إمكانية الوصول يدوياً من الإعدادات.
- قيود الخلفية (Doze/بطارية) لدى بعض الشركات المصنّعة — يلزم استثناء البطارية + خدمة أمامية دائمة.
- التوزيع: تطبيق خاص/داخلي (APK مباشر)؛ متاجر التطبيقات العامة صارمة على تطبيقات التحكم عن بعد.
- الخصوصية: نفس نموذج الأمان (توكن لكل جهاز + تشفير WSS من خطة الأمان) — أولوية أعلى لأن الجهاز شخصي.

**التقدير:** مسار مستقل: 4–6 أسابيع عمل مركّز (قابل للتقسيم، MVP خلال أسبوعين) — يبدأ بعد اعتماد مساري الأداء/الأمان أو بالتوازي بحسب اختيارك.

## ملحق (v3.4.1): المواصفات التقنية التنفيذية لوكيل الأندرويد — جاهزة للتنفيذ
**الحالة:** لم يُنفَّذ في دورتي التطوير (v3.4.0/3.4.1) — ليس إغفالاً: تم التحقق فعلياً من بيئة العمل وتبيّن عدم توفر أي أدوات أندرويد (لا Android SDK، لا Java، لا adb، لا جهاز/محاكي). لا يمكن بناء أو نشر أو اختبار تطبيق أندرويد هنا، وتسليم كود غير مختبَر يخالف قاعدة «التحقق الحي» المتبعة. وهو مصمم كمسار مستقل (A1–A3) يُنفَّذ عند توفر بيئة أندرويد.

**البنية المعمارية:**
- تطبيق Kotlin (minSdk 26) بوحدات: Core (اتصال WebSocket بنفس بروتوكول الوكيل الحالي حرفياً: agent:register / heartbeat+stats / server:command / screen frames / fs_request+fs_write_chunk / screen_chat — لا تعديل على الخادم)، Capture، Control، Ui.
- الشبكة: OkHttp WebSocket + إعادة اتصال تلقائي أسّي + دعم WSS عند تفعيل TLS.
- الشاشة: MediaProjection + VirtualDisplay + ImageReader (بث JPEG)؛ التسجيل: MediaCodec + MediaMuxer (MP4).
- التحكم (بدون root): AccessibilityService — النقر بإحداثيات عبر dispatchGesture، النقر بالاسم عبر بحث AccessibilityNodeInfo (مكافئ clickname)، الكتابة ACTION_SET_TEXT، الرجوع/الرئيسية/التطبيقات الحديثة.
- الواجهة: عربية أولاً بتبويبات مطابقة لتصميم وكيل ويندوز الجديد (v3.4.1).

**الصلاحيات (موافقات إلزامية من المستخدم):** إمكانية الوصول (تفعيل يدوي)، موافقة التقاط الشاشة، إذن الإشعارات، استثناء البطارية + خدمة أمامية دائمة.

**المراحل:** A1 نواة الاستخدام (أسبوعان): اتصال+مشاهدة+لقطة+تسجيل+تحكم أساسي+فتح تطبيقات+نقر بالاسم+دردشة. A2 (أسبوعان): ملفات ثنائي، إشعارات، تحسين بث. A3 اختياري: Shizuku للأوامر المتقدمة + حافظة + أتمتة.

**معيار الإنجاز لكل مرحلة:** اختبار حي على جهاز أندرويد حقيقي يشمل: مشاهدة الشاشة، التحكم الكامل، لقطة، تسجيل، نقر بالاسم، نقل ملف، ودردشة — من لوحة التحكم نفسها دون أي تعديل خادم.
