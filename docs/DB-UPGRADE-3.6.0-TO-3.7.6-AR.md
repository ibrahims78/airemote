# تقرير اختبار ترقية قاعدة البيانات — 3.6.0 → 3.7.6

**التاريخ:** 2026-10-26
**الغرض:** إغلاق البند 1 في `PROJECT_STATE.md §0.3` — «اختبار ترقية قاعدة 3.6.0 → 3.7.6 على نسخة مُصنَّعة».
**الحكم:** نجحت الترقية على **الطبقتين**: سيرفر سطح المكتب (`better-sqlite3`) **36/36**، وسيرفر الويب (`@airemote/server` / libsql) **20/20**، بخروج 0 وبلا فقدان بيانات غير مقصود. ثلاث نتائج تشغيلية يجب أن يعرفها المالك قبل أي ترقية فعلية (القسم 5).

## 1) لماذا هذا الاختبار لم يكن شكلياً

| السبب | التفصيل |
|---|---|
| التثبيت الحالي بدأ من قاعدة فارغة | تثبيت 3.7.6 على Win11 لم يمرّ فوق بيانات 3.6.0، فمسار الترقية لم يُختبر إطلاقاً |
| لا هجرات أعمدة في سيرفر سطح المكتب | `initDb` يستخدم `CREATE TABLE IF NOT EXISTS` فقط، ولا `ALTER TABLE` واحداً؛ أي عمود جديد في 3.7.x كان سيبقى ناقصاً على قاعدة قديمة إلى الأبد |
| مفتاح أسرار SSH مشتق من `jwtSecret` | `getDerivedKey()` = `pbkdf2(jwtSecret, 'airemote-credentials-salt-v1', 100000, 32, sha256)`، و`jwtSecret` محفوظ في `config.json`؛ تغيّره يُفقد كل اعتماد SSH مخزّن |
| طبقة الويب فيها هجرة حقيقية | `ALTER TABLE refresh_tokens ADD COLUMN token_id` + فهرس فريد داخل `try/catch` (يمكن أن يفشل بصمت) + حذف رموز ما قبل 3.7.0 + تقليم تدقيق وإحصاءات |

## 2) الطريقة

لم تُكتب أي قاعدة بيانات يدوياً بالكامل: الهارنس يشتقّ القاعدة من **كود 3.6.0 نفسه**.

| الطبقة | كيف تُبنى قاعدة 3.6.0 |
|---|---|
| سطح المكتب | يُستخرج `server.js` من Git (`32a9d6a`) ويُشغَّل فعلياً، ثم تُنشأ البيانات عبر مساراته: `/api/auth/setup` (bcrypt)، `PUT /api/settings`، `POST /api/credentials` (AES-256-CBC بمفتاح 3.6.0) |
| الويب | يُستخرج مخطط 3.6.0 من `database.ts` (`executeMultiple`) ويُطبَّق على قاعدة libsql، ثم تُزرع صفوف بمدى تواريخ يمتد على حدود التقليم |

ثم تُشغَّل نسخة العمل (3.7.6) على نفس الملف، وبنفس `jwtSecret` في حالة سطح المكتب.

## 5) نتائج يجب أن يعرفها المالك قبل الترقية الفعلية

1. **إعادة دخول واحدة إلزامية** بعد ترقية طبقة الويب: كل رموز التحديث السابقة تُحذف (قرار 3.7.0 لمنع مسار bcrypt البطيء). الجلسات الحالية تنتهي، والدخول بكلمة المرور يعمل.
2. **فقدان بيانات مقصود في طبقة الويب:** عند أول إقلاع لـ3.7.6 يُقلَّم `audit_log` إلى 90 يوماً و`device_stats_history` إلى 30 يوماً. من كان يحتفظ بسجل تدقيق أقدم سيفقده. (طبقة سطح المكتب لا تفعل ذلك: 7 أيام للإحصاءات فقط، وهو سلوك 3.6.0 نفسه.)
3. **`config.json` هو حامل `jwtSecret`:** فقده أو تغييره يجعل كل اعتماد SSH مخزّن غير قابل للفك (`ERR_OSSL_BAD_DECRYPT` — مُثبت بالتحكم السلبي). ما يخفّف الخطر: `appId` ثابت و`deleteAppDataOnUninstall = false` و`DATA_DIR` لم يتغيّر بين 3.6.0 و3.7.6. **يجب نسخه ضمن أي نسخة احتياطية قبل الترقية.**
4. **مفاتيح مزوّدي AI في سيرفر سطح المكتب ما زالت نصاً صريحاً** في جدول `settings` (لا بادئة `enc1:`). التغليف نُفِّذ في طبقة الويب فقط؛ يستحق بنداً أمنياً مستقلاً.

## 6) إعادة التشغيل

```powershell
# طبقة سطح المكتب (تحتاج Electron لأن better-sqlite3 مبني لـABI الخاص به)
$env:ELECTRON_RUN_AS_NODE = '1'
packages\server-desktop\node_modules\electron\dist\electron.exe scripts\test-db-upgrade.cjs --verbose

# طبقة الويب (Node عادي؛ يلزم بناء dist أولاً)
node packages\server\node_modules\typescript\bin\tsc -p packages/server/tsconfig.json
node scripts\test-db-upgrade-web.cjs --verbose
```

الخيارات: `--verbose` و`--keep` (لإبقاء مجلد القاعدة المؤقت)، والمتغيّر `BASE_REF` لتغيير مرجع Git (افتراضياً `32a9d6a`).
