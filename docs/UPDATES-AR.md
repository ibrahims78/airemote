# التحديث من مجلد داخلي — R7 (3.8.31)

## 1) نموذج الثقة

التوقيع مؤجَّل بحسب الخطة §2.2، فالثقة تأتي مما هو موجود فعلاً:

1. **بيان موقَّع** بـEd25519 (`manifest.json` + `manifest.sig`).
2. **مفتاح عام مثبَّت داخل الوحدة** (`SERVER_PUBLIC_KEY`) — لا يُقرأ من المجلد نفسه، فلا
   يستطيع من يملك المجلد أن يزوّر بياناً بمفتاحه.
3. **SHA-256 لكل حزمة** كما في البيان، ويُعاد حسابه محلياً قبل أي تثبيت.

الحزمة تُنسخ إلى منطقة staging **فقط** بعد نجاح التحققين. أي فشل = تقرير بسبب واضح ولا شيء آخر.

## 2) التدفّق

| الخطوة | ما يحدث |
|---|---|
| `POST /api/desktop/update/check` | يقرأ البيان، يتحقق من التوقيع، يقارن الإصدار، يتحقق من الحزمة (حجم + تجزئة) |
| `POST /api/desktop/update/apply` | يتطلب `{version, confirm:true}`، يعيد الفحص، ينسخ إلى `updates/staged/`، ثم يشغّل المساعد المنفصل |
| المساعد `updates/apply-update.cjs` | يوقف السيرفر ← يثبّت الحزمة الجديدة `/S` ← يشغّله ← ينتظر `/health` بالإصدار الهدف ← إن لم يظهر **يعيد تثبيت الحزمة السابقة** ويكتب النتيجة |
| `GET /api/desktop/update` | الحالة + آخر فحص + آخر نتيجة (نجاح/رجوع/فشل) |

**لماذا مساعد منفصل:** NSIS لا يستطيع استبدال ملفات يمسكها التنفيذي العامل؛ لذا تُكتب خطة
JSON ويُشغَّل المساعد بـ`electron.exe` في وضع Node، منفصلاً عن عمر العملية الأصلية.

## 3) الإعداد

| المتغيّر | الافتراضي | المعنى |
|---|---|---|
| `AIREMOTE_UPDATE_DIR` (أو `config.updateDir`) | `<dataDir>/updates/source` | مجلد التوزيع الداخلي |
| `AIREMOTE_UPDATE_SKIP_PROCESS` | — | للاختبار: بلا إيقاف/تثبيت/تشغيل |
| `AIREMOTE_UPDATE_INSTALL_CMD` | — | للاختبار: أمر تثبيت بديل |
| `AIREMOTE_UPDATE_FAKE_HEALTH` | — | للاختبار: إصدار يُعاد بدل قراءة `/health` |

بنية مجلد التوزيع:
```
manifest.json
manifest.sig
server-windows/AiRemote-Server-Setup-v3.8.31-x64.exe
```
(يمكن وضع حزم أقدم بجانبها: تُستخدم كهدف رجوع إذا فشل الإصدار الجديد.)

## 4) الدليل

`e2e-updater` (13 فحصاً): حزمة أحدث تُكتشف وتُتحقق · نفس الإصدار = up-to-date ·
تعديل بايت في الحزمة = `package-size-mismatch` · تعديل البيان بعد التوقيع = `signature-invalid` ·
غياب التوقيع = رفض · staging ينسخ · **المساعد ينجح عندما يظهر الإصدار الهدف** ·
**ويتراجع عندما لا يظهر** · وبلا حزمة سابقة يفشل بنظافة · والسطح HTTP يرفض apply بلا `confirm:true`.

## 5) حدود معروفة

| القيد | التفصيل |
|---|---|
| الرجوع يحتاج حزمة أقدم | إن لم توجد في المجلد يُبلَّغ `failed` بدل ترك تثبيت مكسور |
| لا توقيع للحزمة نفسها | التحقق بالتجزئة + البيان الموقَّع؛ توقيع الملف يُضاف عند تفعيل §2.2 |
| لا تحديث تلقائي بالكامل | الفحص متاح، والتطبيق فعل إداري صريح (قرار: لا تحديث بلا تأكيد) |
| الوكلاء خارج هذا المسار | تحديث الوكيل ما زال `push-file` + `install-agent.bat` |
