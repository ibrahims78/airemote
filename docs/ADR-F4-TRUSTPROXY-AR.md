# قرار النشر F4 — `trustProxy` في السيرفر المكتبي

**التاريخ:** 2026-10-31 · **الشريحة:** R9.4 · **الحالة:** قرار مكتوب، **بلا تعديل كود** · **المنتج:** 3.8.41

---

## 1) الخلاصة التنفيذية

`trustProxy` **غير مفعّل في السيرفر المكتبي** (`packages/server-desktop/server.js`)، و`TRUST_PROXY` **لا يُقرأ فيه إطلاقاً**. المتغيّر يُقرأ فقط في نسخة TS (`packages/server/src/app.ts` و`lib/tls.ts`) المستخدمة في الاختبارات وDocker. لذلك:

- **خلف وكيل عكسي الآن:** كل الطلبات تحمل عنوان الوسيط ⇒ `req.ip` = عنوان واحد ⇒ حدود المعدل تُجمَّع على كل المستخدمين، وسجل التدقيق يسجّل الوسيط لا المصدر.
- **تفعيل `TRUST_PROXY=true` كما هو موثّق في `docker-compose.yml` لا يُصلح المشكلة** في نسخة سطح المكتب، بل قد يوحي خطأً بأنها مُصلحة.
- **قرار الترحيل التجريبي:** النشر المباشر بـTLS على `:3001` داخل شبكة المختبر، **بلا وكيل عكسي** ⇒ يبقى `trustProxy` معطّلاً، وهو السلوك الصحيح (لا انتحال `X-Forwarded-For`).

## 2) الأدلة

| البند | الدليل | القراءة |
|---|---|---|
| تهيئة Fastify في السيرفر المكتبي | `packages/server-desktop/server.js:3212-3215` | `Fastify({ logger:false, ...(tlsOptions ? {serverFactory} : {}) })` — **لا `trustProxy`** |
| حدود المعدل تعتمد `req.ip` | `server.js:3646` (login 5/د) · `3703` (ws-ticket 30/د) · `3680` (refresh 20/د) | كلها per-IP |
| التدقيق يسجّل `req.ip` | 24 موضعاً منها `server.js:3650` (login_failed) · `3876` (sessions export) | خلف وكيل: عنوان الوسيط |
| نسخة TS تقرأ المتغيّر | `packages/server/src/app.ts:37` | `trustProxy: TRUST_PROXY === 'true' \|\| '1'` |
| `TRUST_PROXY` يعفي من TLS في TS | `packages/server/src/lib/tls.ts:21,41` | `behindProxy` ⇒ لا يشترط شهادة |
| إعداد Docker | `docker/docker-compose.yml:24` | `TRUST_PROXY=${TRUST_PROXY:-false}` |

**الخلاصة:** مصدران مختلفان للحقيقة. أي نشر خلف وكيل يجب أن يُصلح السيرفر المكتبي أولاً، لا أن يعتمد على متغيّر البيئة.

## 4) الخيارات

| الخيار | الوصف | التكلفة | المخاطرة | متى يُختار |
|---|---|---|---|---|
| **A. الإبقاء معطّلاً + نشر مباشر TLS** | لا تغيير كود؛ `:3001` مباشرة داخل الشبكة | 0 | لا انتحال؛ لكن لا يعمل خلف وكيل | **الترحيل التجريبي الحالي** |
| **B. تفعيل بقائمة/عدد hops** | `trustProxy: N` أو دالة تثق بـCIDR محددة فقط | تعديل `server.js` + بناء/تثبيت + اختبار انحدار | منخفض إن كانت القائمة مغلقة؛ متوسط إن `true` | أول نشر خلف وكيل |
| **C. `trustProxy: true`** | يثق بأي `X-Forwarded-For` | 0 كود | **مرتفع:** انتحال IP ⇒ تجاوز حدود الدخول وتلويث التدقيق | **مرفوض** |

### القرار الموصى به

1. **للترحيل (الآن): الخيار A.** النشر مباشر TLS، والتوثيق ينص أن `trustProxy` معطّل بقصد.
2. **قاعدة التفعيل:** لا يُفعّل B إلا بعد تنفيذ التصحيح أدناه واختباره، وعند نشر خلف وكيل معروف بعنوان ثابت.
3. **إزالة الالتباس:** توثيق أن `TRUST_PROXY` في `docker-compose.yml` يخص نسخة TS فقط، أو توحيد المصدرين في شريحة لاحقة.

## 5) التصحيح المقترح (لا يُطبَّق في R9.4)

```js
// server.js — قبل Fastify({...})
const rawHops = process.env.TRUST_PROXY_HOPS
const rawList = process.env.TRUST_PROXY_LIST // "10.0.0.0/8,192.168.0.0/16"
const trustProxy = process.env.TRUST_PROXY === 'true'
  ? (rawList ? rawList.split(',').map(s => s.trim()).filter(Boolean)
             : (rawHops ? Math.max(1, Math.min(5, Number(rawHops) || 1)) : false))
  : false
fastify = Fastify({ logger: false, trustProxy, ... })
```

**قواعد:**
- `TRUST_PROXY=true` بلا قائمة/عدد hops ⇒ **يُرفض** ولا يُفعّل (fail-closed)، أو يُسجّل تحذيراً صريحاً.
- القائمة تُقرأ من إعداد السيرفر لا من متغيّر بيئة عشوائي إن أمكن.
- لا تُستخدم `request.protocol/host` في قرارات أمنية (تنبيه fastify ≤5.8.2 في `audit-after2.json`).

## 7) `npm audit` بلا شبكة

- **النتيجة المقيسة:** `npm audit --offline --json` ⇒ `ENOLOCK` (المستودع pnpm بلا `package-lock.json`).
- **القراءة:** لا يمكن تدقيق التبعيات بلا شبكة/مرآة؛ يتطلب `npm i --package-lock-only` ثم اتصالاً بالـregistry.
- **البديل المؤقت:** قائمة تبعيات مثبَّتة + مراجعة يدوية للأخبار الأمنية الحرجة + `pnpm audit` عند توفر الشبكة. يبقى بنداً **مانعاً للإطلاق العام** لا للترحيل المحلي.

## 8) التراجع

القرار A لا يغيّر سلوكاً ⇒ لا حاجة لتراجع. عند تطبيق B: أعد `TRUST_PROXY=false` وأعد تشغيل السيرفر؛ لا تغيير مخطط، والبيانات متوافقة.
