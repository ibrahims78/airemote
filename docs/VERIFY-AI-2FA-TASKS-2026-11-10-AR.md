## 3) المهام المجدولة

### النتيجة: تعمل بعد إصلاح عيب جوهري ✅

| الفحص | النتيجة |
|---|---|
| إنشاء مهمة `ai` / `exec` | `200` مع `id` |
| رفض بيانات ناقصة (`payload`) | `400` |
| رفض `kind` غير صالح | `400` |
| `next_due` للمهمة اليومية `03:30` | `00:30Z` = 03:30 محلي ✔ |
| تشغيل يدوي `exec` على المحاكي | `exit=0` + `FINAL-OK` ✔ |
| تشغيل يدوي `exec` بلا جهاز | «فشلت المهمة: لا يوجد جهاز محدد» ✔ |
| تشغيل يدوي `ai` | نتيجة حقيقية، وعند الازدحام: `Z.ai 429 …` ✔ |
| تعديل (تعطيل/تمكين) | `200` والحالة تتغيّر ✔ |
| حذف + حذف معرّف غير موجود | `200` / `404` ✔ |

### العيب الجوهري: المجدول لم يكن ينفّذ أي مهمة تلقائيًا
- الدليل قبل الإصلاح: مهمة `كل دقيقة` لم تُنفَّذ خلال **200 ثانية** (`last_run_at = null`).
- السبب في `taskNextDue`: عند غياب `last_run_at` كان الاستحقاق يُحسب `الآن + الفاصل` في **كل نبضة**، فلا يتحقق `now >= due` أبدًا — أي أن أول تشغيل تلقائي مستحيل قبل تشغيل يدوي.
- الإصلاح: الأساس أصبح `created_at` (بعد تفسيره UTC لأن SQLite يكتبه بلا منطقة زمنية)، والنبضة من **45 ثانية → 15 ثانية**.
- الدليل بعد الإصلاح: تشغيل تلقائي عند **+75 ثانية** ثم **+135 ثانية** (فارق 60 ثانية)، والنتيجة `exit=0` + `FINAL-TICK`.
