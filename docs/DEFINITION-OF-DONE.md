# DEFINITION OF DONE — AiRemote

> **الإصدار:** 1.0 · **التاريخ:** 2026-10-28 · **المرجع:** `docs/PRODUCTION-PLAN-v2.0-AR.md` (R0)
> **القاعدة الحاكمة:** «لا يُقال تم قبل التحقق». أي بند لا يستوفي قائمته = غير منجز، مهما بدا مكتملاً.

---

## 1) لماذا هذا الملف

الخطة تُقاس ببوابات خروج. هذا الملف يحدد **ما يعنيه «منجز»** على مستوى أصغر وحدة عمل، حتى لا تتحول البوابات إلى رأي.
كل بند هنا قابل للتحقق بأمر أو ملف — لا بعبارة وصفية.

---

## 2) قائمة الإنجاز — تغيير كود (Bugfix / Refactor)

- [ ] السبب الجذري مكتوب (لا وصف العَرَض فقط).
- [ ] التغيير محدود النطاق: لا ميزات جانبية أُقحمت في نفس الالتزام.
- [ ] `node scripts/check-imports.js` يمر.
- [ ] `pnpm --filter <package> typecheck` يمر للحزم المتأثرة.
- [ ] اختبار انحدار يفشل قبل الإصلاح وينجح بعده (أو سبب مكتوب لتعذّره).
- [ ] الحزم المتأثرة أُعيد بناؤها إن كانت تُشحن مبنية.
- [ ] الدليل في `outputs/verify-YYYY-MM-DD/<المرحلة>/` إن كان الإصلاح مرئياً أو سلوكياً.
- [ ] سطر في `PROJECT_STATE.md` §12 يوضح ما تغيّر ولماذا.

---

## 3) قائمة الإنجاز — ميزة جديدة

- [ ] الهدف وسلوك المستخدم مكتوبان قبل الكود.
- [ ] الصلاحية مفروضة **على السيرفر** لا في الواجهة فقط (إن كانت الميزة محمية).
- [ ] الحالات الخمسة مغطاة: تحميل · فارغ · خطأ · نجاح · انتهاء صلاحية.
- [ ] العربية والإنجليزية، RTL وLTR، بلا نص مقطوع.
- [ ] سلوك الفشل محدد: ماذا يرى المستخدم عند الانقطاع/الرفض/المهلة.
- [ ] اختبار آلي أو سيناريو موثّق بخطوات ونتيجة.
- [ ] لا تدهور في مؤشرات الأداء >10% (مقارنة بخط الأساس في `docs/PERFORMANCE-BASELINE.md`).
- [ ] توثيق المستخدم (دليل/مساعدة) محدَّث إن كانت الميزة ظاهرة.

---

## 4) قائمة الإنجاز — تغيير قاعدة بيانات

- [ ] سكربت `up` مكتوب ومُختبر على نسخة حقيقية من الإصدار السابق.
- [ ] سكربت `down` مكتوب ومُختبر (الرجوع ليس نظرياً).
- [ ] نسخة احتياطية مأخوذة قبل الاختبار.
- [ ] البيانات القديمة سليمة بعد الترقية (عدد السجلات + عيّنة محتوى).
- [ ] لا فقدان أعمدة بلا خطة نقل بيانات.
- [ ] السجل في `docs/DB-MIGRATIONS.md`.

---

## 5) قائمة الإنجاز — مرحلة (R#)

المرحلة لا تُغلق إلا بـ:

- [ ] كل مهامها منجزة أو منقولة صراحةً إلى مرحلة أخرى بموافقة المالك.
- [ ] **بوابة الخروج** في الخطة مستوفاة بأرقام، لا بتقدير.
- [ ] ملف دليل في `outputs/verify-*/r#-*/` يحتوي: الخطوات · المتوقع · الفعلي · الحالة `PASS/FAIL/BLOCKED`.
- [ ] تحديث `PROJECT_STATE.md`: §0.1 (قيد التنفيذ) · §0.2 (نقطة الاستئناف) · §12 (سجل).
- [ ] تحديث `CHANGELOG.md` إن تغيّر سلوك ظاهر.
- [ ] لا انحدار: كل اختبارات المراحل السابقة تمر.
- [ ] التزام Git واحد واضح الرسالة يشير إلى `R#`.

## 6) قائمة الإنجاز — إصدار

- [ ] نسخة نظيفة تُبنى من الصفر بأمر واحد.
- [ ] رقم الإصدار موحّد في كل المكوّنات المشحونة.
- [ ] `CHANGELOG.md` محدَّث بالنسخة والتاريخ.
- [ ] حزمة قابلة للتثبيت على جهاز نظيف، ومُختبرة فعلياً.
- [ ] مسار رجوع مُختبر إلى الإصدار السابق.
- [ ] `manifest.json` أُعيد توليده وبصماته مطابقة للحزم الفعلية.
- [ ] لا أسرار ولا ملفات مختبر داخل الحزمة.
- [ ] ملاحظات إصدار بلغة المستخدم.

---

## 7) ما لا يُقبل كدليل على الإنجاز

| لا يُقبل | البديل المطلوب |
|---|---|
| «يعمل عندي» | ملف نتيجة أو لقطة في `outputs/` |
| لقطة شاشة بلا خطوات | خطوات + متوقع + فعلي + لقطة |
| `exit code 0` من سكربت لا يفحص شيئاً | سكربت يفشل فعلياً عند الخطأ (يُختبر بحالة فاشلة) |
| تقدير أداء بلا قياس | JSON من `scripts/perf/` |
| «اختُبر يدوياً» بلا تفاصيل | سيناريو مكتوب بخطوات ونتيجة |
| اختبار يُعلن `SKIP` ويُحسب نجاحاً | `SKIP` = فشل (كما في `scripts/verify.js`) |
