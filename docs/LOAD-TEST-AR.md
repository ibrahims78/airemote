# قياس سقف السعة — R9.1

**التاريخ:** 2026-10-31 · **الأداة:** `scripts/load-test.cjs` · **الإصدار المقيس:** 3.8.39
**البيئة:** نسخة سيرفر مؤقتة (قاعدة في `%TEMP%`، منفذ عشوائي، بلا TLS) على جهاز التطوير — **لا تمسّ السيرفر المثبَّت**.

---

## الطريقة

| المرحلة | الحمل |
|---|---|
| A. HTTP | 40 طلباً متزامناً لمدة 5 ثوانٍ على `GET /api/devices` برمز مصادقة |
| B. مشاهدون | 60 مشاهداً على جلسة واحدة (كل مشاهد يحتاج تذكرة WS) |
| C. بثّ التعليقات | مشاهد واحد يبثّ 200 حدث ليزر إلى بقية المشاهدين |
| D. وكلاء | 25 وكيلاً يسجّلون ويردّون على `ping` |

الأرقام من تشغيل واحد كامل (`load-result.json`)؛ الأداة تُعيد نفس البنية عند كل تشغيل.

---

## النتائج

| القياس | القيمة |
|---|---|
| HTTP throughput | **848 طلباً/ثانية** (40 متزامناً) |
| زمن الاستجابة p50 / p95 / p99 | **42 / 74 / 89 ms** |
| أخطاء HTTP | **0** |
| تذاكر WS | **30 صادرة / 60 مطلوبة** (30 مرفوضة بحدّ المعدل) |
| مشاهدون فُتحوا | **30** خلال **39 ms** |
| تسليم بثّ التعليقات | **5800/5800 = 100%** · p95 **2 ms** |
| وكلاء متصلون | **25/25** |
| ذاكرة العملية | بدأت 73MB → **243MB** (+170MB) |
| أقصى تأخّر حلقة أحداث | **61 ms** |

---

## القراءة الصحيحة

1. **السيرفر ليس عنق الزجاجة في المسار النصي:** 848 rps بصفر أخطاء، وتسليم بثّ 100% بزمن 2ms، وتأخّر حلقة أقصى 61ms.
2. **السقف الحقيقي على المشاهدين هو حدّ التذاكر، لا القدرة:** `POST /api/auth/ws-ticket` محدود بـ**30/دقيقة لكل IP**. لذلك 60 مشاهداً في دقيقة واحدة يستحيل بالتصميم؛ 30 فقط يدخلون.
   - هذا **ضابط أمني مقصود** (منع إغراق المصادقة)، وليس عطلاً.
   - من يحتاج أكثر: يوزّع الانضمام على أكثر من دقيقة، أو يرفع الحدّ في الإعداد عند وجود عدة عناوين/مستخدمين.
3. **الذاكرة تنمو مع الأجهزة والمشاهدين:** +170MB بعد 25 وكيلاً و30 مشاهداً و200 حدث بثّ. لا تسريب واضح (القيمة تعود بعد إغلاق الجلسات في تشغيل `--quick`: +88MB).
4. **ما لم يُقس:** ترميز الفيديو (الوكلاء وهميون، لا يرسلون إطارات)، TLS، وقاعدة البيانات على القرص الشبكي. هذه تُقاس في مرحلة لاحقة على أجهزة حقيقية.
