## 0. كيف تُقرأ هذه الخطة

هذه ليست قائمة مهام. هي **نظام تشغيل لـ90 يومًا**، مبني على أربع قواعد:

1. **كل مرحلة لها بوابة خروج (Gate)** لا تُفتح إلا بأدلة، لا بوعود.
2. **كل مهمة لها مخرج ملموس** (كود، وثيقة، تقرير، أو قياس) ومالك واحد.
3. **الاختبار ليس مرحلة أخيرة** — لكل مرحلة خطة اختبار خاصة تُكتب قبل التنفيذ.
4. **التوثيق ليس ملحقًا** — كل تغيير معماري يُنتج ADR، وكل واجهة تُنتج عقدًا، وكل إصدار يُنتج ملاحظات وقياسًا.

**رموز الأولوية:**
- **P0** — يوقف الإصدار إن لم يُنجز.
- **P1** — مطلوب في المرحلة، لكن يمكن تأجيله أسبوعًا بمبرر مكتوب.
- **P2** — تحسين، يُنقل للمرحلة التالية إن ضاق الوقت.

**رموز التقدير:** أيام شخصية (pd) لشخص واحد متمرّس، ولا تشمل الاجتماعات والمراجعات.

## 1. الملخص التنفيذي

### 1.1 الوضع الحالي في سطور

AiRemote 3.13.1 منصة ناضجة وظيفيًا: أدوار، تدقيق، وصول غير مراقب، مصفوفة قدرات، جلسات وكيل‑بوكيل عبر Relay، طرفية، AI، مراقبة، وتسجيل. لكنها تعاني ثلاث فجوات تحدد قيمتها السوقية:

| الفجوة | الدليل من الكود | الأثر |
|---|---|---|
| **جودة وسائط غير مثلى** | جسر WebRTC يُغذّى بإطارات JPEG ثم يفكّها ويرسمها على canvas ويعيد ترميزها (`packages/agent-desktop/rtc.html`) | CPU مضاعف، نص مموّه، زمن أعلى، وتجربة أقل من المنافسين |
| **لا تشفير طرفي حقيقي** | `iceServers: []` ⇒ WebRTC على LAN فقط؛ المسار الافتراضي JPEG عبر السيرفر؛ التحكم عبر WebSocket يمر بالسيرفر | السيرفر يرى الوسائط والمدخلات، ولا يمكن ادعاء خصوصية صارمة |
| **تغليف وتوثيق خارجي ضعيف** | README يشير إلى 3.7.0، لا `git remote`، 199 ملفًا غير ملتزم، CI ويندوز فقط، لا مستودع منشور | المنصة غير مرئية للسوق، ولا يمكن تقييمها أو المساهمة فيها |

### 1.2 ما الذي تغيّره الخطة

| المجال | قبل | بعد 90 يومًا |
|---|---|---|
| مسار الوسائط | JPEG → canvas → إعادة ترميز | إطار خام → ترميز عتادي H.264 → WebRTC مباشر |
| الشاشة الساكنة | 30 إطارًا/ثانية من محتوى متطابق | صفر إطار عند السكون، وإطارات متغيّرة فقط |
| التشفير | TLS إلى السيرفر + توكن bearer | هوية جهاز Ed25519 + E2E للوسائط والتحكم + مفاتيح مختومة |
| الشبكة | LAN فقط لـWebRTC | STUN/TURN + ICE restart ⇒ يعمل خارج الشبكة |
| الاختبار | بطارية محلية 45/45، CI ويندوز | هرم اختبار + مصفوفة منصات + بوابات أداء وأمان |
| التوثيق | وثائق عربية داخلية ممتازة | حزمة إنجليزية/عربية منشورة: معمارية، تهديد، بروتوكول، تشغيل، اختبار |

### 1.3 خارج النطاق (صراحةً)

- ميزات NectarLink الاستهلاكية: إشعارات الهاتف، SMS، المكالمات، كاميرا الهاتف، تطبيقات الهاتف في نوافذ.
- إعادة كتابة المنصة بلغة أخرى.
- دعم متاجر التطبيقات العامة.
- WebRTC Simulcast متعدد المشاهدين (يُقيَّم في الربع التالي).
- ترخيص تجاري أو تسعير.

## 4. المبادئ المعمارية الملزمة

هذه المبادئ تُحسم الخلافات، ولا تُفتح للنقاش داخل المراحل:

1. **لا تعِد ترميز ما سبق ترميزه.** أي إطار يُرمَّز مرة واحدة، ويُمرَّر كما هو حتى العرض أو التسجيل.
2. **لا تُنتج إطارًا لم يتغيّر.** السكون يعني صفر إطارات، لا إطارات متطابقة.
3. **السيرفر لا يرى ما لا يحتاج رؤيته.** الوسائط والمدخلات تمر مشفّرة طرفيًا؛ السيرفر يوجّه ولا يفكّ.
4. **القدرات بيانات، لا شيفرة.** مصفوفة واحدة (`capabilities.json`) يستهلكها السيرفر والوكيل واللوحة.
5. **كل ادعاء مقيس.** لا تُنشر ميزة أداء بلا رقم وأمر إعادة إنتاج.
6. **التوافق الخلفي ملزم.** أي تغيير كاسر يحتاج نسخة بروتوكول جديدة ودعمًا مزدوجًا لإصدار واحد.
7. **الأمان الافتراضي هو الرفض.** كل قدرة حساسة معطّلة حتى تُفعَّل بوعي، وكل اتصال غير مقترن يُرفض.

### 9.5 الاختبار المطلوب في المرحلة 1

**اختبارات وحدة (إلزامية):**
- `VideoEncoder`: إطار واحد ← حزمة صحيحة؛ إطار تالف ← رفض بلا انهيار.
- `dirty`: شاشتان متطابقتان ← صفر إطارات؛ تغيير 10% ← إطار جزئي.
- `ABR`: فقد 1% ← خفض fps؛ فقد 5% ← خفض دقة.
- `identity`: مفتاح مختوم يُفتح؛ مفتاح تالف يُرفض؛ توقيع challenge يُتحقق.

**اختبارات تكامل:**
- وكيل ↔ متصفح عبر LAN: أول إطار < 1.5s، تحكم يصل، لا إعادة اتصال خلال 10 دقائق.
- وكيل ↔ متصفح عبر TURN: نفس السيناريو مع 100ms تأخير مصطنع.
- انقطاع الشبكة 5 ثوانٍ: ICE restart، استئناف بلا إعادة اقتران.

**اختبارات E2E:**
- اقتران، بث، تحكم، إغلاق، إعادة اتصال.
- التحقق من أن حزمة التحكم لا تظهر نصًا صريحًا في سجلات السيرفر.

**اختبارات أمان:**
- توكن مسروق بلا مفتاح خاص ← رفض.
- توقيع خاطئ ← رفض + تدقيق.
- بصمة DTLS غير متطابقة ← تحذير للمستخدم.

**اختبارات أداء:**
- سكون 60s: 0 إطار، CPU < 2%.
- حركة 60s: p95 < 80ms LAN، CPU < 20%.
- TURN: p95 < 150ms، فقد < 1%.
