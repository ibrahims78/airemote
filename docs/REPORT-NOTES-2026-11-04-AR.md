## 1) الجدار يشغّل بثًّا تلقائيًا عند العودة

**السبب الجذري (بالكود):** وضع `preview` في العارض كان يبدأ متصلًا بالتصميم:

```ts
// قبل الإصلاح — ScreenViewer.tsx
const [started, setStarted] = useState(() => popout || preview || sessionStorage.getItem(sessionKey) === '1')
```

أي أن أي مربع يُرسم ⇒ يتصل فورًا. وبما أن مربعات الجدار محفوظة في `localStorage`
(`airemote-live-board-v1`)، فعند العودة إلى الصفحة تُستعاد المربعات وتشتعل الاتصالات بلا إذن.

**ما نفّذت:**
- خاصية جديدة `autoStart?: boolean` في `ScreenViewer` (سطر 47 و119).
- الحالة الأولية صارت: `popout ? true : (preview ? !!autoStart : sessionStorage…)` (سطر 290).
- فرع `preview` يرسم الآن **بوّابة**: زر «بدء مشاركة الشاشة» ولا يوجد أي اتصال قبل الضغط.
- الجدار يحفظ التخطيط فقط: `tiles.map(({key, deviceId}) => …)` — ولا يُحفظ `running` إطلاقًا، فالعودة تعني دائمًا «متوقف».

**الدليل:** `git show f4f9336 -- packages/dashboard/src/components/ScreenViewer.tsx` (فرق +398/−190 مع الجدار).

## 4) كلمة سر عند الاتصال وكيل↔وكيل

**لم يُنفَّذ.** أوضّح الوضع الحالي بدقة:

- الاتصال **سيرفر → وكيل** (أي فتح الشاشة من اللوحة) يمرّ بجلسة تحكم، وإن كان للجهاز كلمة سر تحكم يظهر: «التحكم بكلمة سر — هذا الجهاز يتطلب كلمة سر للتحكم» (قرار D40). هذا مُثبت بالاختبار الحيّ على WIN10 وWIN11.
- الاتصال **وكيل → وكيل** يستخدم `POST /api/relay/request` مع `access: 'control'` ثم `decision{accept:true}` — **بلا أي كلمة سر**، ثم تُصدر `view-ticket`.

**المطلوب لتنفيذ الميزة** (نطاق واضح، لم أبدأه):
1. عمود/حقل اختياري `control_password_hash` على الجهاز (موجود أصلًا لمسار السيرفر — يُعاد استخدامه).
2. `POST /api/relay/request` يقبل `password` ويتحقق قبل إنشاء الجلسة (`403` عند الخطأ، مع عدّاد محاولات).
3. `decision` لا تُقبل إلا بعد تحقّق ناجح، والتذكرة تُربط بالجلسة المتحقّقة.
4. واجهة الوكيل: حقل كلمة سر في نافذة الطلب + رسالة رفض واضحة.
5. اختبار: طلب بكلمة صحيحة/خاطئة/بلا كلمة، وإعادة استخدام التذكرة.

## 5) قائمة التطبيق تُجمّد الواجهة

**السبب الجذري (مؤكّد):** الشريط العلوي منطقة سحب في إلكترون:

```css
.app-titlebar { -webkit-app-region: drag; }
.app-titlebar button, a, input, select { -webkit-app-region: no-drag; }
```

والغطاء الخلفي للقائمة `<div className="app-menu-backdrop">` — أي **`div` لا يُستثنى** ⇒ إلكترون يفسّر النقر عليه كسحب نافذة ولا يوصله إلى React، فلا تُنفَّذ `onClick` ولا تُغلق القائمة. وبما أن الغطاء `position: fixed; inset: 0; z-index: 80` فإنه يبقى فوق الواجهة كلها ⇒ «لا استجابة في أزرار الواجهة». نفس العيب في قائمة المستخدم.

**ما نفّذت:**
- استثناء صريح: `.app-menu-backdrop, .app-menu-pop, .app-user-pop { -webkit-app-region: no-drag; }`.
- مخرج احتياطي: `Escape` يُغلق القائمتين (حتى لو ابتُلع أي نقر مستقبلًا).

**الدليل:** `control-room.css` (الأسطر 1108–1112) و`DashboardLayout.tsx` (تأثير `Escape`)، والالتزام `d24dd07`.

## 7) الأداء: fps منخفض واستهلاك معالج عالٍ

### القياس (WIN10-VM، 4 أنوية، عبر `typeperf`-style sampling داخلي)

| الحالة | وكيل (مجموع العمليات) | عامل الالتقاط | fps في العارض |
|---|---|---|---|
| خامل | ≈ 5.4% | 0% | — |
| **أثناء البث** | **≈ 24.1%** | **9%** | **4** |

أي **≈ 33% من 4 أنوية مقابل 4 إطارات/ثانية**. على جهاز أضعف أو شاشة أكبر يصبح 50–70% منطقيًا — وهو ما تراه.

### أين يذهب المعالج (بالسطر)

1. **بصمة التغيّر عبر `GetPixel`** — `capture-gdi-worker.cs:143-155`:
   ```csharp
   long h = 17; int sx = Math.Max(1, b.Width/16), sy = Math.Max(1, b.Height/16);
   for (int y = 0; y < b.Height; y += sy)
     for (int x = 0; x < b.Width; x += sx) {
       Color c = b.GetPixel(x, y);          // ← نداء GDI+ لكل بكسل
       h = h * 31 + (c.R + c.G + c.B) / 3;
     }
   ```
   `GetPixel` أغلى عملية قراءة بكسل في GDI+ (نداء + تحويل لون لكل عيّنة). الشبكة 16×16 ⇒ 289 نداءً لكل إطار، 12 مرة/ثانية ≈ **3,500 نداء/ث**، وكلها على الإطار الكامل (1600×900) قبل أي تصغير.
2. **تصغير كامل + ترميز JPEG لكل إطار متغيّر** — `Scale()` ثم `use.Save(ms, jpg, ep)` (سطر 288).
3. **BitBlt لكامل الشاشة كل دورة** (سطر 114) بمعدل 12/ثانية، ثم `Thread.Sleep` قصير.

### هل يمكن تخفيضه «بشكل كبير»؟ نعم — وهذا ترتيب الأثر

| الخطوة | الأثر المتوقع | الجهد |
|---|---|---|
| استبدال بصمة `GetPixel` بـ`LockBits` + مقارنة مصفوفة بايتات (توقف مبكر عند أول اختلاف) | **الأكبر** — إزالة آلاف نداءات GDI+ لكل إطار | متوسط (C# محلي) |
| مقارنة على صورة مصغّرة (مثل 320px) بدل الإطار الكامل | يقلّل البصمة والتصغير معًا | منخفض |
| تقليل معدل المحاولة عند السكون (min-interval تصاعدي) | يخفض الحمل الخامل | منخفض |
| ترميز JPEG بأبعاد نهائية مباشرة (StretchBlt إلى 1280) بدل تصغير بعد التقاط كامل | يوفّر نسخة صورة كاملة لكل إطار | متوسط |

بهذه الحزمة يكون الهدف الواقعي **خفض حمل الالتقاط بنسبة 50–70%** مع بقاء نفس الجودة — وهو فرق النوعية الذي تراه في AnyDesk/Chrome Remote Desktop (فهما لا يقرآن بكسلات عبر واجهة عالية المستوى، بل يعملان على مخزن بتّي متصل + مقارنة مناطق).

**ما لم يُنفَّذ:** لم أُعدّل كود الالتقاط بعد. أي تغيير فيه يحتاج: تعديل `.cs` ⇒ `build-gdi-worker.cjs --force` ⇒ بناء الوكيل ⇒ نقل `app.asar` إلى الضيفين ⇒ قياس مقابل على نفس الجهاز. هذا دورة كاملة لم أنجزها في هذه الجولة، ولن أقدّمها كـ«مُصلَحة» قبل قياسها.
