# إصلاح واجهة وكيل ويندوز — 2026-11-07 (بعد 3.14.0)

> **الخلاصة:** واجهة الوكيل في 3.14.0 كانت **ميتة تمامًا**: `app.js` لم يكن يُحلَّل أصلًا داخل Electron.
> الوكيل يتصل (main.js سليم) فتبدو اللوحة «متصل»، لكن النافذة تعرض «متوقف» بلا معلومات اتصال وبلا إعدادات.
> السبب عيب واحد، والإصلاح سطر واحد.

---

## 1) العَرَض كما رصده المالك

| العَرَض | الحقيقة المقيسة |
|---|---|
| الوكيل متصل والواجهة تقول «متوقف» | الحالة بقيت على قيمة HTML الافتراضية — لم يُنفَّذ سطر JS واحد |
| لا تظهر معلومات الاتصال | `#inf-server` و`#inf-devid` بقيا «—» (يملؤهما `applyStateLabels`) |
| قسم الإعدادات لا يفتح | مستمعو `.sec-hdr[data-target]` لم يُربطوا قط |

## 2) السبب الجذري — مقيس لا مُستنتَج

```
preload.js        contextBridge.exposeInMainWorld('airemote', …)   ← خاصية عالمية غير قابلة للحذف
renderer/app.js   const airemote = window.airemote || new Proxy(…)  ← إعلان معجمي بنفس الاسم
```

النتيجة عند الإقلاع، داخل Electron فقط:

```
Uncaught SyntaxError: Identifier 'airemote' has already been declared
  at renderer/app.js:1:1
```

إعلان `const` على المستوى الأعلى لا يستطيع إنشاء ارتباط معجمي عالمي إذا كان الاسم خاصية غير قابلة للتهيئة على `window`، فيفشل **الملف كله في التحليل**. لا يوجد استثناء لكل سطر: كل ما بعد السطر الثامن لم يوجد أصلًا، ولذلك بقيت البطاقة على «متوقف» وبقيت الحقول فارغة والأكورديونات بلا مستمعين.

**لماذا لم يكتشفه المسبار؟** `probe.cjs` يفتح `index.html` بالملف في Chrome: لا preload ⇒ لا خاصية ⇒ لا تعارض. العيب موجود في بيئة التشغيل الحقيقية فقط. أُدخل الغلاف في `15d68ac` وأصلح `pageErrors 1 → 0` **في وضع الملف**، وفي الوقت نفسه كسر التطبيق الحقيقي.
