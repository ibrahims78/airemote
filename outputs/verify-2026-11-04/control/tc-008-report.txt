# TC-008 — agent starts automatically after a guest boot (PASS)

Evidence collected during the 3.13.0 rollout:

1) Autostart entry exists (scripts/autostart-3130.ps1 output):
   TASK_HITS=1
   TASK \AiRemote Agent (Elevated),N/A,Running
   SERVICES=0 · STARTUP_DIR=0
   => the agent is launched by a logon scheduled task with RUN LEVEL = HIGHEST, not by a service.

2) Boot measurement (vmrun -T ws reset Win10_Pro_Custom.vmx, exit 0 at ~15:41):
   AGENT pid=3932 start=15:42:06
   AGENT pid=7484 start=15:42:18
   AGENT pid=7516 start=15:42:19
   AGENT pid=7596 start=15:42:19
   AGENT pid=8624 start=15:42:29
   WORKER capture-gdi-worker-098abca6 start=15:42:27
   => first agent process ~60s after reset, worker on the new hash ~21s later, without any manual step.

3) Server view right after boot: devs.cjs => WIN10-VM online agent=3.13.0.

Verdict: PASS — the agent returns automatically after a reboot and registers with the new build.
Caveat: the runner is a HIGHEST scheduled task, so a filtered-token guest shell cannot stop it
(see the WIN10 elevation lesson in swap-results.txt).
