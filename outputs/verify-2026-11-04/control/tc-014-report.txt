# TC-014 — the monitor wall does not start streaming on its own (PASS)

Method: load "/" authenticated, then hook window.WebSocket AFTER the page is fully loaded
(the first attempt installed the hook on the login page, so the navigation wiped it — that run
was invalid and is superseded by this one).

Measurement after 7s of idle:
  ws = 0 screen connections
  preview canvases laid out: 300x150, 1280x720, 1600x677 (sized from the device resolution)
  no [data-tb] toolbar buttons rendered

Interpretation: the wall lays out a canvas per remembered device but opens no /screen WebSocket
until the user activates a tile. With a session added by hand the count becomes ws = 1
(see ui/preview-wall-measure.txt), which proves the instrument actually counts streams.

Verdict: PASS — no background stream is started by the wall itself.
