## 1. ما نُفِّذ

| # | العنصر | التفاصيل |
|---|---|---|
| 1 | **`devices.code`** | عمود جديد: 9 أرقام، فريد (فهرس فريد)، يُولَّد عند الحاجة ويُعبَّأ للأجهزة القائمة عند الإقلاع |
| 2 | **هجرة غير كاسرة** | `PRAGMA table_info` ثم `ALTER TABLE … ADD COLUMN` — قاعدة قديمة بلا العمود تعمل بلا فقدان بيانات |
| 3 | **`contacts`** | جدول ملكي: `owner_id`, `display_name`, `device_id`, `device_code`, `group_name`, `favorite`, `note` + فهرس على المالك |
| 4 | **`GET /api/devices/by-code/:code`** | يحل الرمز لمالكه/المشرف فقط، ويُعيد 404 للغريب (لا يكشف الوجود) |
| 5 | **`GET/POST/PATCH/DELETE /api/contacts`** | مقيّدة بالمالك على السيرفر، مع بحث نصي وترتيب (المفضلة أولاً) |
| 6 | **تدقيق** | `contact_created` و`contact_deleted` في `audit_log` |

### عقد الـAPI (مختصر)

```http
GET    /api/contacts?q=…                 → [{ id, displayName, deviceId, deviceCode, group, favorite, note, device:{id,name,status,isOnline} }]
POST   /api/contacts  { displayName, deviceId | deviceCode, group?, favorite?, note? }
PATCH  /api/contacts/:id  { displayName?, group?, favorite?, note? }
DELETE /api/contacts/:id
GET    /api/devices/by-code/:code        → { id, name, code, status, isOnline }  | 404
```

## 2. النتائج (18/18)

| المجموعة | الفحوص |
|---|---|
| الهجرة | A1 العمود أُضيف · A2 جهاز قديم حصل على رمز 9 أرقام |
| الرمز | B1 يظهر في القائمة · B2 المالك يحلّه · B3 الغريب 404 |
| الإنشاء | C1 يُنشأ · C2 يظهر مع بيانات الجهاز · C3 المفضلة تُحفظ |
| العزل | D1 لا يظهر لمستخدم آخر · D2 لا يعدّله · D3 لا يحذفه |
| التعديل | E المفضلة والمجموعة تتغيّران |
| الرمز كمدخل | F الإنشاء برمز يربط الجهاز · F2 الربط صحيح |
| التحقق | G رمز قصير → 400 |
| الحذف والتدقيق | H1 يحذف المالك · H2/H3 صفوف التدقيق |

**خطأ اكتُشف أثناء التطوير:** استعلام الحذف كان يجلب `id, display_name` بلا `owner_id`، فكان الشرط `row.owner_id !== p.userId` صحيحاً دائماً → **كل حذف يفشل بـ404** حتى للمالك. أصلحه الاختبار قبل الالتزام.

## 3. ما لم يُنفَّذ بعد في R3

| # | البند | الحالة |
|---|---|---|
| 1 | شاشة دفتر العناوين في اللوحة | مؤجّلة إلى R6 (نظام التصميم) — الـAPI جاهز |
| 2 | **الوصول غير المراقب** (كلمة مرور لكل جهاز) | الشريحة الثانية |
| 3 | أدوار موسّعة (`operator`) وصلاحية دقيقة لكل جهاز | الشريحة الثانية |
| 4 | Presence محسّن (آخر ظهور، إصدار، دقة) | جزئياً موجود عبر `info`؛ يحتاج عرضاً |
| 5 | بحث موحّد (أجهزة + جهات اتصال) | لاحقاً مع R6 |

**قاعدة:** لا تُغلق R3 قبل الوصول غير المراقب والصلاحية الدقيقة لكل جهاز — لأنهما جوهر «الاتصال بلا تدخّل بشري».
